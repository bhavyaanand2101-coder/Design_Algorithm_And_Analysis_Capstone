Phase 1: Courier Problem Design and Planning (20 Marks)

1.1 Mathematical Formulation of Entities

The system models the courier logistics problem through two primary abstractions: Heterogeneous Parcel Entities and a Navigable Urban Road Network Graph.

Parcel Entity: Each package Pi is represented as a 7-tuple: Pi = ⟨ idi, desti, wi, vi, pi, di, bi ⟩ where desti is the destination node, wi is weight in kg, pi ∈ {1, 2, 3, 4, 5} is priority tier, di is deadline SLA in hours, and bi is base monetary utility value.

Composite Business Utility Value Function: To balance business revenue and delivery urgency, we define:
Utility Value vi = round(bi · pi + max(0, (24.0 - di) · 2.0))
High-priority packages with tight deadlines earn high utility values, incentivizing the Knapsack packing engine to prioritize urgent deliveries.

Road Network Model: The physical territory is an undirected weighted graph G = (V, E, W), where V represents customer delivery locations, junctions, and the Central Depot (Node 0). Edge weights w(u, v) represent navigable road lengths in kilometers.

Phase 2: Package Prioritization and Box Filling (20 Marks)

2.1 Multi-Criteria Comparator & Sorting Analysis

The system implements a three-tier comparison function for package prioritization: Primary: Deadline (ASC) ➔ Secondary: Priority Tier (DESC) ➔ Tertiary: Value Density (DESC)

2.2 0/1 Knapsack Dynamic Programming Formulation

Let N be the count of prioritized parcels and W be vehicle payload capacity. The state space table DP[i][w] represents the maximum business utility attainable considering a subset of the first i parcels with cumulative weight ≤ w:
DP[i][w] = max(DP[i-1][w], DP[i-1][w - wi] + vi)   when w ≥ wi, else DP[i-1][w]

Phase 3: Route Maker and Graph Processing (20 Marks)

3.1 Dijkstra Shortest Paths & Metric Distance Matrix

From the backtracked knapsack parcel manifest, active delivery stops S = {Depot} ∪ {desti} are extracted. Dijkstra's algorithm is executed with a binary min-heap from each active stop u ∈ S, computing all-pairs shortest distances D[u][v] in O(|S| · (|V| + |E|) log |V|) time.

3.2 Nearest-Neighbor TSP with 2-Opt Local Search Untangling

An initial delivery circuit is synthesized using the greedy Nearest-Neighbor heuristic (O(K²)). Subsequently, 2-Opt local search iteratively reverses segments (i &dots; j) whenever replacing edges (a, b) and (c, d) with (a, c) and (b, d) reduces tour length.

Empirical Optimization Result (Metropolitan City Scenario, 50 Parcels):
• Raw Nearest-Neighbor Tour: 105.81 km
• 2-Opt Refined Tour: 85.47 km (19.22% distance reduction achieved in 4 swap passes, taking 0.093 ms)
• Turn-by-Turn Road Transit Sequence: Hub ➔ Highland Heights ➔ Airport ➔ Riverfront ➔ Tech Corridor ➔ Lakeside ➔ Airport ➔ Industrial Park ➔ University ➔ Harbor ➔ Suburban ➔ Greenwood ➔ Hospital ➔ Commerce Square ➔ Sunset Blvd ➔ Hub.

4.2 Four Future Optimization Proposals

1. Space-Optimized 1D Rolling Knapsack Array: Transition from 2D matrix (O(N · W)) to 1D array (O(W)) with backward iteration to fit entirely within L1/L2 CPU cache.
2. Goal-Directed A* Search with Contraction Hierarchies: Replace uniform Dijkstra with Euclidean distance heuristic, reducing node expansions by 80–95%.
3. Lin-Kernighan Metaheuristic (LKH) / 3-Opt: Dynamically test k-edge reconnections to escape local 2-opt traps for large stop clusters (K > 50).
4. Multi-Vehicle Capacitated VRP (Cluster-First Route-Second): Deploy K-Means / Sweep clustering to partition parcels among multi-truck fleets, solving TSP per cluster in parallel.
